## 9.25 工具 schema、TACO 函数评分、Harness 生产交接与轻量快照

原问题：环境 JSON Schema 的 `["string", "null"]` 等联合类型直接传入只支持单个类型名的 HarnessForge Tool，模型尚未调用就失败。现在仅转换 HF 展示/声明类型，调用时仍验证原 schema；必填、nullable、联合类型和未知参数规则不被放宽。

原问题：部分 TACO 函数测试把返回值包在外层列表，`True` 与 `[True]` 直接比较导致正确程序记失败。现在按上游 call-based 约定先比较完整返回值，再比较包装中的返回值，保留真实列表返回及现有数字精度规则；STDIO 不变。训练评分器升级 v2，旧成绩不回写，不与新父代混用。

原问题：HARNESS 最后验证工具可在缺少定位/方向报告的情况下落位，生产阶段和验证阶段的职责容易混淆。现在完整父代复制工具返回真实上游模板、报告路径；Meta 依次分析、制定方向、生成完整包后再验证。缺报告及不完整包返回可继续处理的回执；同候选最多三轮可执行性检查，逐次记录诊断，由同一 Meta 修复。仍然由 Meta 决策组件/候选/接受，只在原任务严格涨分后激活。报告存在并不代表其推理必然正确，工具不评价诊断内容。

实际隔离测试另发现：验证器把宿主父目录名拼入 Python 包名，包含点号的目录会让有效 Harness 假性导入失败。隔离副本统一使用 `validation_round` 包目录，宿主路径只承担存储作用，验证仍在独立 Python 进程。

快照改为 `versions/index.json` + `model_XXX` / `harness_XXX` / `meta_XXX`；未变化组件不重复保存，模型继续引用已保留的独立 checkpoint，Meta 仅保存各版经验库内容。轮次快照记录 parent/candidate/selected 组合；`compose_task` 可构造 model_001+harness_002 等评测状态，不自动部署。进度账本同时识别新的上下文引用回执与旧快照拷贝回执，旧实验兼容读取。

验证：100 项项目回归通过；包含真实上游工具实例、实际隔离 Harness 静态/导入/构建及候选状态落位、去重/交叉组合和上下文账本衔接。另用冻结 B3 中 `deepcoder_taco:0733c4ef…` 的原始 10 用例，在与 pipeline 相同的 LinuxSandbox 配置中执行：正确 `is_orthogonal` 为 10/10，固定返回 False 为 4/10 且整题仍失败。本次未发 API 请求、未启动 GPU 三轮实验、未改写历史结果。新一轮需要用修复后的执行器重新获得父代成绩。

## 9.23 恢复 Meta 原生编程能力

原问题：常驻实现显式关闭 shell、使用只读沙箱并设置 `environments=[]`，桥接层还用操作白名单和仅运行目录可写的限制拒绝工具修复；Meta 因而无法像原生 Codex 一样自行调试或补充工具。这不是 DeepSeek 模型能力不足。
